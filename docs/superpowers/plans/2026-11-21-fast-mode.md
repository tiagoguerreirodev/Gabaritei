# Fast Mode for Claude and Codex Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Each role (and the Gerar overrides) can turn Fast Mode on, for both Claude and Codex, shown only where it can apply.

**Architecture:** `RoleConfig` gains a `fast` flag (saved with the role). The runner turns it into each CLI's own setting. The catalog says which Codex models support it, and Claude is always shown because support is only visible per run.

**Tech Stack:** Rust (Tauri 2, `ts-rs`), Solid.js + TypeScript, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-21-cli-fed-model-options-design.md` (PR 2 section and Amendment); mechanisms in `docs/superpowers/specs/2026-11-21-catalog-spike-findings.md`.

**Depends on:** PR 153 (the catalog). Branch off it, or off `main` after it merges. Open a GitHub issue first (milestone M4 · AI generation) and name the branch `issue-<n>-fast-mode`.

## Global Constraints

- UI text pt-BR; code, comments, docs, commits in English. Conventional Commits.
- Commands thin; domain logic plain Rust. After Rust type changes run `cargo test --manifest-path src-tauri/Cargo.toml` and commit the regenerated `src/bindings/` (never hand-edit).
- No migration: roles are JSON in `settings`; `fast` is `#[serde(default)]` so saved roles still load.
- No real AI calls in tests: fake CLIs and fake catalog sources only.
- Fast Mode use is **not** recorded in packages, provenance or notes (owner decision).
- Mechanisms (verified in the spike): Claude `--settings '{"fastMode":true}'` (works with `--setting-sources ""`; needs extra usage on the account, otherwise the run proceeds without Fast Mode, no error); Codex `-c service_tier="priority"` (key accepted by `--strict-config`; effect not observable from events).
- Argument rule: when `fast` is false the runner passes **nothing** new (no `--settings`, no `service_tier`).
- Before the PR: `cargo test`, `cargo clippy --all-targets -- -D warnings`, `cargo fmt --check`, `npm test`, `npm run lint`, `npm run typecheck`; the `spoiler-auditor` agent on the diff; the owner runs `/preflight`.

## Review Focus

1. **Roles saved before this change** (no `fast` key) load with `fast: false` and save back unchanged.
2. **Switching to a Codex model without a Fast tier** clears `fast` in the UI, and the backend refuses a run that still has it (when the list is loaded).
3. **`fast` off adds no arguments** to either CLI (a stray `--settings` would change isolation).
4. **Switching a role's agent** resets `fast` to false.
5. **Codex list unavailable (free text):** the checkbox is shown (support unknown), and the backend allows it.
